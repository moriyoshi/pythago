Channel optimizations 1-4, 2026-11-16

Implemented changes:
- Typed nonblocking native selects complete ready operations synchronously.
- Future, worker, and operation handles are allocated only when waiting.
- Workers retire their own handles. Successful Python awaits perform no cancellation callback or redundant cleanup.
- Send and receive callbacks use fewer metadata arguments. Ready operations do not parse loop/token IDs or look up the loop.
- Each Python channel method has one coroutine frame; common scalar/byte results avoid intermediate owned Objects.
- chan *aio.Buffer transfers explicit buffer leases without payload copies; ordinary chan []byte retains copying semantics.
- Repeated Go exports reclaim previously released pins while Python remains attached, bounding streaming pin retention.
- The shared FFI trampoline and purego dependency were not changed (step 5 is separate).

Method: Linux arm64, Cortex-X925 cores 5-8, GOMAXPROCS=4, Go 1.26.11,
CGO_ENABLED=0, free-threaded CPython 3.14t. Same machine and pinned CPU set as
baseline. Scalars: five 600 ms samples; byte variants: three 600 ms samples.
All figures are medians per completed message. 32 workers measure throughput
cost, not individual-await latency. Go allocation metrics exclude Python heap.

The ownership-aware variant has fixed export/memoryview overhead. For Go ->
Python at 64 KiB it is slower than the optimized copy path (about 5 us vs 2.9 us),
but at 1 MiB it is faster. For Python -> Go, 64 KiB leases take about 3.5 us
instead of 13.5 us for the optimized copy path, and eliminate roughly 98.6% of
Go allocation bytes compared with the original implementation. At 1 MiB the
lease still allocates about 1 KiB of Go metadata instead of a 1 MiB slice.
Payloads are reused and consumers do not scan every byte: zero-copy MB/s is
equivalent message volume, not measured memory bandwidth.

Ownership and cancellation:
- Go senders relinquish use of aio.NewBuffer(data, readOnly) and its mutable data after sending.
- Python sends borrow any C-contiguous buffer; the sender must not modify shared mutable memory until receiver release/acknowledgement.
- Go receivers Close leases before Python finalization; Python receivers release or collect their memoryviews.
- Cancellation joins unfinished workers. A transfer racing cancellation can already have committed, as before.
- Cancelled unsent leases and queued/dropped receive leases are released, including loop shutdown.

Validation:
- aio, py, and asgi tests run three times with CPython 3.14t and three times with CPython 3.13 GIL.
- Targeted channel tests repeatedly cover ready/no-Future behavior, successful/no-cancel behavior, cancellation races, automatic worker retirement, close/drain, shutdown, nil values, and failed Future creation.
- Buffer tests cover zero-copy aliasing, read-only exports, typed-view flattening, GC lifetime, explicit release, resize protection, cancellation and shutdown cleanup, and bounded pin retention.
- go vet ./aio ./asgi and gofmt checks pass.
- The race detector could not link the translated native image with CGO enabled; forcing internal linking also failed in purego dynamic relocations. No race-detector pass is claimed.
