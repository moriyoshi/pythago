# pythago plan

CPython embedded in Go programs built with `CGO_ENABLED=0`: libpython is translated by
[bao](https://github.com/moriyoshi/bao) from python-build-standalone (PBS) archives and
linked into the Go binary. Go calls Python and Python calls Go, and third-party C extensions
(wheels) load unmodified.

This file is the product plan. The spikes behind it, with measurements, failures and
lessons, are in `.agents/docs/LTM/` (index: `.agents/docs/LTM/INDEX.md`);
`.agents/docs/JOURNAL.md` logs work not yet consolidated there. The spike concluded on
2026-11-15 as **feasible**.

## 1. Goals and scope

- **Embed CPython in a pure-Go binary.** No cgo and no libpython shared library. The only
  dynamic libraries are the system C library family: libc, libm, libdl, libpthread and
  libgcc_s.
- **Single-file deployment for pure-Python applications and small extensions.** The
  stdlib and application code are served from a Go `fs.FS` (for example `embed.FS`).
- **Large native stacks run from an environment on disk** next to the binary: PyTorch +
  CUDA (5 GB), vLLM (7.6 GB). Embedding them is impractical, and they `dlopen` their own
  libraries through `$ORIGIN`-relative paths.
- **Bidirectional FFI.** Go runs Python code and converts values; Go functions and modules
  are exposed to Python. Errors and panics cross the boundary as exceptions.
- **Python threads are backed by goroutines**, and goroutines enter Python with bounded
  OS-thread use.
- **Both GIL and free-threaded CPython.** GIL is the default variant; free-threaded is
  opt-in (§9).
- **Targets:** linux/arm64 and linux/amd64 (glibc ≥ 2.18, see §4 step 8; C extensions
  need ≥ 2.28) first,
  then darwin arm64/amd64, then windows amd64/arm64 (pure Python first).
- **Non-goals:** M:N virtual threads (frozen; `.agents/docs/LTM/feasibility-and-threading-decision.md`); a
  Go-implemented allocator; re-initializing the interpreter in one process.

## 2. Architecture overview

```
PBS full archive ──► pythago-dist ──► dist package, generated by the consumer (per version × variant × target)
  (bitcode libpython,   fetch + verify       .syso objects (bao output)
   static deps,         LTO-lower (ld.lld)   symbols_<os>_<arch>.{go,s} (pinned versions)
   PYTHON.json)         inittab, glue,       stdlib.zip / .pyc tree (embed.FS)
                        symtab, bao,         register.go: py.RegisterImage(SymbolAddr0())
                        version pinning
                                                   │ import _ ".../dist/..."
Go program ──► py (public API) ──► C glue (pythago_glue.c, pythago_py.c) ──► libpython
                │  importer: fs.FS meta-path finder
                │  extshim:  SHN_ABS ELF of Py* symbols → dlopen(RTLD_GLOBAL)
                └  env:      environments (venv-like) and the wheel installer
```

- **One bao image per executable**, so the dist package *is* the binary's native image.
- **Address mode plus purego.** There is one bootstrap (purego's fakecgo). Go reaches every
  C API function and data object through one symbol table, `pythago_symtab`. Calls go
  through `runtime.cgocall` and a small assembly thunk with fixed arities (`py/ccall*`),
  about 33 ns on arm64 with no allocation, except float signatures, which use purego's
  `RegisterFunc`. Go functions are entered from C through `crosscall2` with a frame the
  glue decodes (no reflection), about 113 ns per Python→Go call.
- **C glue covers what Go must not or cannot do:**
  - PyStatus/PyConfig handling;
  - the thread hooks and the start/join handshake;
  - the trampoline for Go functions;
  - building tuples, lists and dicts in one call from tagged values;
  - object kind checks when constructing native views;
  - signal handling and the fork handler;
  - the `_pythago` builtin module.
- **Native read-only views use pre-derived layouts.** Unicode headers are read using
  compiler-derived definitions for the exact Python build, GIL variant and target.
  Buffer metadata comes directly from the active stable-ABI `Py_buffer` export. No
  per-object length/kind/data cache is kept. Refcounts still go through
  `Py_IncRef`/`Py_DecRef`; types are checked through the glue.

**No prebuilt native images are distributed (user decision, 2026-11-16).** pythago ships
source only. Each consumer generates its dist package locally with `pythago-dist`, into
its own module, and imports it for its side effect:

```go
//go:generate env -u GOOS -u GOARCH go run github.com/moriyoshi/pythago/cmd/pythago-dist -python 3.13 -target $GOOS/$GOARCH -o pydist
import _ "example.com/app/pydist"
```

- **Committing is the consumer's choice:** whether to commit the generated package (about
  60 MB of `.syso` per target plus the stdlib zip) or generate it in CI.
- **Consumers need only Go and network access (2026-11-16).** The default build
  (`-mode shared`, §4) runs no native tool at all:
  - **bao is a Go module dependency** (`github.com/moriyoshi/bao/build`, PR #31), run in
    process by `pythago-dist` at the version go.mod pins. `-bao`/`PYTHAGO_BAO` substitutes
    an executable, e.g. to try a bao branch.
  - **The glue is prebuilt** (`glue/prebuilt/<abi>-<goos>_<arch>.o`, embedded in package
    `glue`). These are maintainer-built, reproducible objects, not native images: CI
    rebuilds them byte for byte from source (`ci/glue.sh` for Linux, `ci/darwin.sh glue`
    on a Mac for darwin, whose objects are pinned to the macOS 26.5 SDK and target
    macOS 11). User decision, 2026-11-16; darwin SDK pin, 2026-11-17.
  - PBS `install_only_stripped` archives are fetched and verified as before. `.tar.gz`
    needs only `tar`; zstd is used only for LLVM and the full archives.
  - `go generate` for one target takes under a second when the PBS archive is cached.
- **LLVM is needed only for `-mode lto`, for rebuilding the glue (`-prebuild-glue`), and
  for ABIs without a prebuilt glue object.** It comes from `-llvm`, else `PYTHAGO_LLVM`,
  else the verified LLVM release (23.1.5) is fetched once and checked against GitHub's
  digest. Only clang, lld, llvm-ar/nm/readobj/readelf and `lib/clang` are extracted, 721 MB
  of 13 GB. On macOS, LLVM publishes arm64 builds only, and only clang is extracted (the
  darwin glue); an Intel Mac uses its own clang unless `-llvm` is given.
- `-print-toolchain` prints `llvm=` and `bao=` (empty: built in); `ci/lib.sh` uses it.
- Everything lives under the user cache: downloads, LLVM, and the LTO-lowered libpython
  keyed by its inputs.

## 4. Native image build (`pythago-dist`)

Two modes produce the same dist package API. Every CI tier passes on both: unit and qemu,
floor, GPU (torch, vLLM), for 3.13 and 3.14t on arm64 and amd64.

**`-mode shared` (default since 2026-11-16).** bao translates PBS's `install_only_stripped`
`libpython3.X[t].so.1.0` directly (`-linux-shared-object`), together with the glue:
1. Fetch and verify the `install_only_stripped` archive.
2. Glue: the prebuilt object for the ABI and architecture (`glue.Prebuilt`), else compile
   `pythago_glue.c` and `pythago_py.c` with `pythago_symtab` (needs LLVM). The glue is
   `-mno-outline-atomics` on arm64. `pythago_static.c` (the `atexit` and `stat64`
   wrappers) is LTO-only.
3. bao build (in process) with the glue as input, `-linux-shared-object`, `-wrap` for the
   four pthread functions (which also wraps the library's imports, PR #30), and
   `-linux-max-symbol-version GLIBC_2.18`. No partial link runs: a single `.o` input needs
   no combine step.
4. Emit as below. `register.go` also calls `py.RegisterExports(SharedObjectExports(),
   SharedObjectExport)`, which adds the library's dynamic exports to the symtab lookups.
- **Glue rule:** wrapping applies to the glue too, so the glue's fallbacks call
  `__real_pthread_*`. Calling `pthread_*` would recurse into `__wrap_*`.
- **Image size:** smaller. For 3.13, the `.syso` total is 23.5 MB against 35.7 MB on
  arm64, and 23.8 MB against 34.6 MB on amd64, since the input is the stripped library.
  The PBS shared library is itself PGO+LTO-built.

**`-mode lto`.** Lowers the full archive's bitcode; needs LLVM. Kept as the alternative,
e.g. for a custom `config.c` or ahead-of-time extension linking.
LTO steps per (Python version, variant, target), ported from `.agents/attic/spike/s1/build.sh`:
1. **Fetch** `cpython-<ver>+<tag>-<triple>-[freethreaded+]pgo+lto-full.tar.zst`. Verify
   the GitHub release sha256 digest (and the attestation where available).
2. **Read `PYTHON.json`:** the object list (not `libpythonX.Y.a`; the archive misses
   objects and has duplicate member names), the static dependency links, and
   `glibc-max-symbol-version`.
3. **Regenerate `config.c` (the inittab)** without readline, curses, tk, dbm and the test
   modules.
4. **LTO-lower** the bitcode members with LLVM ≥ the PBS clang (`ld.lld -r --lto-O2`),
   giving one object of about 31k sections.
5. **Link-time wraps** (`--wrap`): `pthread_create`, `pthread_join`, `pthread_detach` and
   `pthread_exit` only. Once bao `-wrap` (PR #11, merged) is adopted, this step moves into
   bao. That needs the user's go-ahead.
6. **Compile the glue** and generate `pythago_symtab` from the default-visibility `_?Py*`
   symbols plus `pythago_*`.
7. **Run bao:** `build -target linux/<arch> -sysroot <sysroot> -symbol pythago_symtab
   -linux-max-text-alignment 4096 -link-archive <deps…> -link-archive <libgcc |
   compiler-rt builtins>`.
8. **Bind dynamic symbol versions at the image's glibc floor:** bao
   `-linux-max-symbol-version GLIBC_<floor>` (PR #18, adopted 2026-11-15). The floor is
   the newer of 2.18 (`minGlibc`) and the archive's `glibc-max-symbol-version` (2.17 today).
   - **glibc < 2.18 is not supported (user decision, 2026-11-15).** bao's native-TLS
     runtime needs `__cxa_thread_atexit_impl` (GLIBC_2.18). With the cap at 2.18 it binds a
     real version, so the loader rejects older glibc at startup instead of failing at
     the first TLS access. Every other import binds ≤ GLIBC_2.17.
   - Imports with nothing at or below the cap are listed in bao-manifest as
     `linux_imports_above_version_cap`. Today those are only the weak, optional
     `getentropy` and `sem_clockwait`.
   - **The floor was never true at runtime (found 2026-11-16).**
     - Built against a glibc 2.34+ sysroot, capped imports of the symbols that moved into
       libc.so.6 in 2.34 (`pthread_*`) still named libc.so.6, so binaries failed to start
       on glibc < 2.34. Fixed in bao PR #34 (not merged).
     - Weak imports above the cap were fatal in bao's shared-object binder: fixed in #35.
       Archive (LTO) input still fails on weak code references, so LTO images need glibc
       2.30+.
     - DT_NEEDED listed ld-linux first on arm64, so rtld kept its minimal malloc on
       glibc < 2.32 and asserted at the second `RTLD_GLOBAL` dlopen. Fixed in bao #36.
     - **With bao #36 (unmerged; go.mod pinned) the 2.18 floor holds in shared mode:**
       jessie (2.19) and buster (2.28) pass on both architectures, for 3.13 and 3.14t.
     - `ci/floor.sh` now runs a program through Debian jessie's (2.19) and buster's (2.28)
       own loaders on both architectures; version numbers alone missed both bugs.
   - The glue defines pre-2.33 `stat64`/`fstat64`/`lstat64` wrappers (calling
     `__xstat64` and friends), since the PBS sqlite references them and PBS's own link
     gets them from glibc 2.17's `libc_nonshared.a`.
9. **Emit the stdlib** as a `.pyc` tree or zip for `embed.FS`, the `register.go` file and
   the license notices.

LTO lowering takes about a minute per target and needs LLVM. The lowered `libpython.o` is
cached per version, variant and target.

Sysroots for cross builds are assembled from distribution packages, each checked against
its index digest. That is how the amd64 build on arm64 works
(`.agents/docs/LTM/glibc-floor-and-amd64.md`).

## 5. Threading model (decided)

- **Python threads are goroutines,** each locked to its own OS thread.
  - libpython's `pthread_create` → `pythago_py_spawn`, which hands the thread to a spare
    (`Config.SpareThreads`, default 4) or starts a goroutine.
  - The start, join, detach and exit handshake is entirely in C (futex flags plus a
    registry keyed by `pthread_t`).
  - Each Python thread gets a fresh OS thread that exits after join.
- **Invariant: at most one Python thread state per OS thread.** Free-threaded 3.14 merges
  refcounts on behalf of a detached owner thread state.
- **`py.Do(fn)`** takes an admission slot (`Config.Slots`), locks the OS thread, and
  attaches that thread's cached thread state, which a pthread-key destructor frees when the
  thread exits.
  - It nests: inside `Do`, inside Go functions called from Python, and inside `Release`.
- **`py.Release(fn)`** detaches the thread state and gives back the admission slot around
  blocking Go code.
- **The thread cap** (`Config.MaxThreads`, `SetThreadLimit`) raises "can't start new
  thread" instead of hitting Go's fatal thread limit.

## 6. Process model

`sys.executable` is the program itself. Python re-executes it for multiprocessing
spawn/forkserver workers, `subprocess.run([sys.executable, ...])`, compile workers and
servers.
- **Re-executed children are marked** with `PYTHAGO_PYTHON_EXECUTABLE=<path>`.
  `py.IsPythonCommand()` detects them, and `py.Main(cfg, os.Args)` runs CPython's
  command-line semantics (`PyConfig_SetBytesArgv` with `parse_argv`, then `Py_RunMain`)
  with the same configuration.
- **`py.Run(cfg, fn)`** makes that dispatch impossible to forget. It runs `Main` for a
  re-executed child, and otherwise does `Init`, `fn`, `Finalize`, then exits.
  `pythago-dist` can also generate a `main` wrapper.
- **Everything a child needs comes from `Config`, so it applies in both modes:**
  - Go modules, through `Config.Modules`;
  - environments, through `Config.Environment`;
  - stdlib and app filesystems;
  - `Config.Setup`.

  A Go module created ad hoc after `Init` does not exist in children.
- **Forked children (fork without exec) cannot run Go.** A `__register_atfork` child
  handler makes later threads plain libc threads, and Go functions raise `RuntimeError`.
- **`Config.MultiprocessingStart`** defaults to `"forkserver"`, which is 3.14's Linux
  default, so 3.13 applications also get children that can run Go. Set it to `""` to keep
  Python's default.

## 7. Main thread and signals

- **Python's main thread is `py`'s dedicated init thread.** It holds the main thread state
  and finalizes.
- **`py.OnMain(fn)`** runs fn there, for code that must be on the main thread:
  `signal.signal`, servers that install handlers, `asyncio` with signal handling. Under
  `py.Main`, the command line itself runs on the main thread.
- **Go owns the signal handlers** (`install_signal_handlers = 0`).
  - `signal.signal()` returns `None` for Go's handlers. Passing `None` back restores Go's
    handler through `_pythago.restore_signal`; in forked children it restores `SIG_DFL`.
  - **`Config.PythonSignals`** lets Python install its own handlers (SIGINT →
    `KeyboardInterrupt`, as `python` does). Off by default; useful for `Main` and CLI-like
    programs.

## 9. Variants: GIL by default, free-threaded opt-in

- GIL (`cp3XX`) and free-threaded (`cp3XXt`) are separate dist packages, chosen by the
  consumer's `pythago-dist -variant`.
- **Free-threaded scales:** 7× on 8 threads (arm64), and torch CPU work 5.4× on 8 threads.
  But the ecosystem lags:
  - stable-ABI (abi3) wheels cannot load in 3.14t, so vLLM is GIL-only;
  - some wheels re-enable the GIL at import (triton).
- `pythago-dist` and `env` check wheel tags against the variant at build or install time
  and report what cannot load.

## 10. Extensions and environments

- **Primary mechanism:** a code-free ELF of SHN_ABS `Py*` symbols, at the live addresses
  from the symtab.
  - It is loaded with `dlopen(RTLD_GLOBAL)` from a memfd before the first extension import.
  - Extensions then `dlopen` normally from real files.
  - Only `^_?Py` symbols are exported, so a wheel's vendored OpenSSL or zlib never binds
    to ours.
  - Proven with numpy, cffi, markupsafe, torch+CUDA, `torch.compile`, triton, flashinfer
    and vLLM.
- **`Config.Environment`** is a venv-like directory. `py` adds its site-packages with
  `site.addsitedir` (so `.pth` files work), prepends its `bin/` to `PATH`, sets
  `VIRTUAL_ENV`, and loads the shim automatically. Existing venvs work as they are,
  provided their Python version and ABI match the image.
- **Wheel installer (`env`):**
  - merges `purelib`/`platlib`;
  - installs `*.data/scripts` into `bin/` (JIT builds need tools such as `ninja` on PATH);
  - keeps file modes and writes `RECORD` and `INSTALLER`;
  - checks tags against the image.
- **Embedded wheels:** installed on first use into a content-hashed environment in the
  user cache directory, keeping the `$ORIGIN`-relative layout.
- **Ahead-of-time bao translation** is an optional later optimisation, only for small
  self-contained extensions. It needs bao features: component namespaces, deferred
  constructors, C++ unwinding.

## 12. Public API (py) — current and planned

**Exists:**
- lifecycle: `Init`, `Finalize`, `Main`, `IsPythonCommand`;
- threads: `Do`, `Release`, `SetThreadLimit`, `ReadStats`, `Slots`, `FreeThreaded`;
- running code: `Exec`, `Eval`, `ExecIn`, `Import`;
- values: `Object` (`Attr`, `SetAttr`, `Item`, `SetItem`, `Call`, `CallKw`,
  `CallMethod`, `Len`, `Truth`, `Str`, `Repr`, `Go`, `Int64`, `Float64`, `GoString`,
  `Bytes`, `NewRef`, `Close`), `From`, `Tuple`, `None`;
- errors and Go code: `Error`, `Func`, `NewFunc`, `NewModule`;
- `Config`: `Symtab`, `Home`, `ProgramName`, `SearchPaths`, `Slots`, `MaxThreads`,
  `SpareThreads`, `Setup`.

**Added in M1 (done 2026-11-15):** `Run`, `OnMain`, `RegisterImage`, `ErrMainBusy`;
`Config.Environment`, `Modules`, `PythonSignals`, `MultiprocessingStart` and
`NoExtensions`. The extension shim (`py/internal/extshim`) loads automatically.

**Added in M2:** `Config.Stdlib` and `Config.Files` (`fs.FS`), `RegisterStdlib`,
`RegisterStdlibZip`.

**Added 2026-11-16:**
- `RegisterExports`, for shared-object images.
- `(*Error).SystemExit`.
- `(*Object).UnsafeBytes`: a bytes object's storage without copying. It is valid while a
  reference is held, and goroutines may read it without a thread state. `aio`'s writers
  send from it.
- Package `aio`: `aio.Configure(&cfg)` makes the Python module `goaio` importable, in
  this process and in `sys.executable` children.
- **Zero-copy arrays through the buffer protocol** (`py/buffer.go`):
  - **Python → Go:** `py.WithView[T](obj, writable, fn)` is the safe form: it borrows
    the memory for exactly fn's duration and releases on return or panic. Underneath are
    `(*Object).Buffer(writable)`, `(*Buffer).Bytes`, `py.View[T](buf)`, `Shape`,
    `Strides`, `Format`, `Contiguous` and `Close`. `(*Object).BufferInto(b, writable)`
    re-exports into a closed (or zero) Buffer, reusing its allocations, for read loops. This works
    for any exporter: bytes, bytearray, memoryview, array, numpy, and torch via
    `.numpy()`.
  - **Go → Python:** `py.NewBuffer[T](data, readOnly, shape...)` returns a
    `pythago.GoBuffer` (a glue heap type). The slice is pinned (`runtime.Pinner`) until
    Python frees the object. Its deallocator queues a token that Go drains on its next
    entry; it never calls Go. `Stats.GoBuffers` counts the pinned slices.
  - Typed views need C-contiguous memory and a little-endian or native format matching T
    in kind and size. Neither side locks the memory.

**Added 2026-11-20:** `Config.FusedBytes`, opt-in Go-owned `bytes` (the fusion): `asgi`
reads request bodies into Go memory laid out as `bytes` objects, which become the objects
without a copy. The allocator is `internal/fusion` (no public type yet); `Init` installs
an object-allocator hook and fails on CPython versions the design is not verified on
(3.13 with the GIL, 3.14 free-threaded). See `.agents/docs/arena-design.md` sections 13 to
15 and the README.

**Planned:**
- **Later:** iteration, context-aware `DoContext`, type objects from Go, and DLPack for
  device (GPU) arrays; a public `FusedBytes` type, and fused `wsgi` bodies and `aio`
  channel messages.

**M5. asyncio integration (`aio`), then darwin, then Windows** (pure Python). darwin
pure Python done 2026-11-17 (`ci/darwin.sh`, both variants and arches); its C extensions
2026-11-18 (the shim loads lazily: extension imports, ctypes dlopen and C API lookups,
subinterpreter creation, fork). Windows remains.
- **Windows: extract-and-load (decided 2026-11-18).** At `Init`, `python313.dll` and the
  glue (a small DLL linked against it) are written to a cache directory and loaded with
  the Windows loader, which then reuses that module for every later import of
  `python313.dll` by name: stdlib `.pyd`, wheels and their helper DLLs, `ctypes`. An
  in-memory copy (bao `-windows-dll`, PR #44) works for the interpreter but is unknown to
  the loader under that name, so no extension DLL can bind to it; it stays an option for
  programs without extension modules. Python→Go calls use one `syscall.NewCallback`
  dispatcher instead of `crosscall2`; checked under Wine 11.22 (journal 2026-11-18).
- **`aio`: ported (2026-11-16)** from `.agents/attic/spike/goaio`, on top of `py`. Python
  imports `goaio`, which provides:
  - `GoEventLoop` (proactor: goroutines do the I/O with `net`, Go's resolver included);
  - `GoSelectorEventLoop` (`SelectorEventLoop` over Go's netpoller);
  - `goaio.run(coro, selector=False)`.

  uvicorn takes `--loop goaio:GoEventLoop` directly.
- **Changes from the spike:**
  - **Waiting.** A loop waits in a Go function under `py.Release`, not in a C event. Each
    Python thread is its own OS thread now, so blocking there blocks only that loop's
    thread. There is no glue change, so the prebuilt glue stays valid in both build modes.
  - **Blocking fds.** These are fds Go's netpoller won't take, such as asyncio's pidfds for
    child processes. The selector watches them with `ppoll` plus an eventfd for
    cancellation.
  - **Errors.** Name resolution failures raise `socket.gaierror` (`EAI_*`), as stock
    asyncio does.
- **BufferedProtocol (2026-11-16):** a `GoEventLoop` transport whose protocol is an
  `asyncio.BufferedProtocol` reads with no extra copy.
  - Go exports the buffer that `get_buffer` returns (`read_into`, `Object.Buffer`) and a
    per-connection goroutine reads into it.
  - The export is released on the loop thread before `buffer_updated`.
  - Pausing holds a completed read, and EOF behind it, until resume, as asyncio's proactor
    loop does. `set_protocol` across kinds is served by copying.
  - **Inline reads:** `read_into` first tries a non-blocking read on the loop thread, and
    only hands off to the reader goroutine and the netpoller when no data is waiting.
  - Measured with a `BufferedProtocol` (MB/s):

    | Buffer | GoEventLoop | stock selector |
    |---|---|---|
    | 256 KiB | 8.3–8.45k | 8.5k |
    | 64 KiB | 6.3–6.4k | 8.6–8.8k |
    | 4 KiB | 834–843 | 1.6–2.0k |
- **Tests:** `aio` runs in the unit tier, on both variants, natively and under qemu.
  - **Real wheels (2026-11-21):** `aio` and `asgi` also load pinned binary wheels
    (`ci/test-wheels.txt`: pyreqwest, pyzmq), fetched per target by
    `internal/tools/fetchwheels` (PyPI's sha256) and extracted by `internal/testwheels`
    (`PYTHAGO_TEST_WHEELS`), in every tier: unit and qemu, Wine, darwin, native Windows.
  - **Readers and writers (2026-11-21):** `GoEventLoop.add_reader`/`add_writer` keep a
    GoSelector whose watchers post `EV_READY` into the loop's completion queue, so
    `zmq.asyncio` runs on every loop and in ASGI apps.
- **`asgi` (2026-11-16, prototype):** `asgi.Configure(&cfg)`, then
  `asgi.New("module:app", Options)` returns an `http.Handler`.
  - Workers are Python threads, each running a GoEventLoop with its own lifespan.
  - Request goroutines post to a worker's loop through `aio.Loop`. Response actions
    (start and first body combined, then body, read more, abort) are queued for the
    goroutine.
  - **Inline requests (the default since 2026-11-17; `Options.LoopThread` opts out):**
    the request goroutine runs the application as an eager task on its worker's loop,
    and runs the requests queued meanwhile in the same batch (flat combining). A worker lock (`aio.Hooks`) keeps the
    loop thread out while a goroutine does, and the loop thread serves queued requests
    itself before it waits. Requests that await real I/O continue on the loop thread.
  - **Worker processes (`workers.Spawn`, 2026-11-17; package `asgi` until it moved):** a
    supervisor listens once and runs n copies of the executable; each inherits the
    listener as fd 3 (`ExtraFiles`) and takes it with `workers.InheritedListener`.
    Spawned (fork+exec), never forked: the Go runtime cannot run after `fork()`.
    Restarts with backoff, gives up after repeated early exits, SIGTERM then SIGKILL on
    shutdown, Pdeathsig, and GOMAXPROCS set to each worker's share of the CPUs.
    `asgiserve -processes n`, `wsgiserve -processes n`. Workers stop when
    `workers.NotifyContext` is done. On Windows (2026-11-18) the listening socket and a
    stop pipe's read end are inherited handles; a worker accepts with an overlapped
    AcceptEx completing on an event (the shared socket's completion port is the
    supervisor's) and serves connections on Go's I/O completion port; the supervisor
    closes the pipe to stop it, and the pipe closes too when the supervisor exits.
  - Body bytes are written zero-copy, with backpressure past a high-water mark.
    Disconnects reach `receive()`.
  - **Go-owned request bodies (opt-in, `py.Config.FusedBytes`, landed 2026-11-20):**
    request body chunks up to 64 KiB are read into fused slots and become `bytes` without
    a copy; otherwise the request-memory and lease paths run as before. Status and
    measurements: `.agents/docs/arena-design.md` section 15.
  - FastAPI works: lifespan, validation, streaming, docs.
  - Performance: with two cores and `GOMAXPROCS=4` it is within a few percent of uvicorn
    + uvloop (69.9k against 72.5k req/s). On one core `net/http`'s ~9 µs per request
    competes with Python. See `.agents/docs/LTM/asgi-server-protocol.md`.
  - **Response trailers (`http.response.trailers`):** done, with strict rules (see
    `.agents/docs/LTM/asgi-server-protocol.md`). Every response header and trailer field is validated, and request
    trailers are never passed on.
  - **WebSockets:** done, on `github.com/coder/websocket` (a new dependency). The
    origin check, handshake and message rules are enforced in Go; see
    `.agents/docs/LTM/asgi-server-protocol.md`.
  - **WebSockets over HTTP/2 (RFC 8441):** done. They need `GODEBUG=http2xconnect=1` in
    the process environment, Go's own switch (issue #71128). Other `CONNECT` requests
    get 405.
  - **`http.response.pathsend`:** done, sent with sendfile(2), with
    `Options.PathSendRoots` for confinement.
  - Not yet: permessage-deflate (off on purpose).
- **`wsgi` (2026-11-17):** `wsgi.New("module:app", Options)` returns an `http.Handler`
  for a PEP 3333 application. No event loop: each request runs on the goroutine
  net/http serves it on, through `py.Do`, so the admission slots (`Config.Slots`) are
  the server's thread pool. The body is read and the response written with the thread
  state detached while the client is slow; yielded chunks are flushed one by one, list
  results get a Content-Length; `wsgi.file_wrapper` uses sendfile. Status and headers
  are validated in Go (`internal/httpfield`, shared with `asgi`), hop-by-hop headers are
  refused, request headers with "_" are dropped. Flask 3.1 matches gunicorn route for
  route. Several processes: `workers.Spawn`, which serves any handler. See
  `.agents/docs/LTM/wsgi-server.md`.

## 15. Private and fragile CPython surface (recheck every minor release)

- `PyConfig._init_main`, plus a second `Py_InitializeFromConfig` to run the main phase.
  3.14 removed `_Py_InitializeMain`.
- `PyPreConfig` with `utf8_mode`; `Py_RunMain`; `PyConfig_SetBytesArgv` with `parse_argv`.
- `_Py_brc_queue_object` behaviour: merging on behalf of a detached owner. This is the
  reason for the one-thread-state-per-OS-thread invariant.
- `signal.signal` returning `None` for handlers it did not install.
- multiprocessing re-exec arguments (`-c … --multiprocessing-fork`, forkserver).
- The glue includes internal headers only in the frozen VT code, and in the fusion's
  reader check (`glue/pythago_fusioncheck.c`: `pycore_object.h`, `pycore_stackref.h`,
  built as `Py_BUILD_CORE_MODULE`).
- **The fusion (`Config.FusedBytes`)** relies on, per minor release (arena-design.md
  section 13, "What it relies on"): freed objects keeping the bytes before `ob_type`
  (`_Py_MergeZeroLocalRefcount`, `new_reference`); `_Py_TryIncref*` touching only those
  bytes; mimalloc's `debug_offset` reuse within a size class without QSBR; gc callbacks
  bracketing a stop-the-world; `bytes` freed through `PyObject_Free` and resized through
  `PyObject_Realloc`. `pythago_fusion_supported` admits a new minor version only after
  `TestFusedBytesStaleReader` passes against its headers.

## 16. Risks and open questions

- **Python headers for C extension builds at runtime** (`torch.compile`/inductor,
  flashinfer JIT) are not in the embedded stdlib, so those workloads need the stdlib on
  disk (PYTHONHOME or `Config.Home`). Option: extract `include/` (and `sysconfig` data)
  to a cache directory on demand, and point `sysconfig` at it.
- **`Config.Files` is snapshotted at `Init`,** since the import index is immutable. Live
  reloading from `os.DirFS` needs `SearchPaths` or an environment on disk instead.

- **macOS:** the runtime-generated dylib with absolute exports, and code signing on arm64,
  are untested.
- **Windows extensions:** covered by extract-and-load (the real loader binds them); export
  stubs plus IAT patching and an in-memory `.pyd` loader were rejected as fragile.
- **No native amd64 measurements yet** (qemu only).
- **libffi** on 16/64 KiB-page arm64 kernels under the text-alignment cap.
- **Consumer first-build cost:** resolved by the shared mode. The first `go generate` fetches
  only the PBS `install_only_stripped` archive (about 30 MB) and runs nothing native. The LTO
  mode still fetches about 1 GB of LLVM and lowers for about a minute per target.
- **Prebuilt glue drift:** an edit to `glue/*.c` without rebuilding `glue/prebuilt`
  ships stale glue in shared mode. `ci/glue.sh` catches it in CI for Linux, and
  `ci/darwin.sh glue` on a Mac for darwin (`ci/darwin.sh glue-update` rebuilds them).
- **Interpreter speed under bao (2026-11-16): allocation-heavy Python runs about 2× slower
  than stock**, which puts uvicorn about 29% behind on the same loop.
  - The cause is bao's TLS descriptor thunk: a full register spill plus
    `pthread_getspecific` on every `_Py_tss_tstate` read, about 50% of instructions in a
    str-churn loop.
  - Reported to bao. **bao PR #32 (fast path, not merged) brings uvicorn to stock
    speed:** asyncio equal on two cores, uvloop equal. GoEventLoop on two cores matches
    stock uvloop.
  - Allocation churn stays 1.1–1.3× stock, from about 32 instructions per TLS access.
    bao's planned glibc static TLS should close it.
  - **Repin go.mod to bao main once #32 merges.** See
    `.agents/docs/LTM/bao-tls-and-uvicorn-parity.md`.
- **Go functions in forked children are unavailable by design;** document it prominently.
